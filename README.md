# Todo Board — 미니 기능 구현 라이브 코딩 연습

알고리즘성 문제 대신, 실제 면접에서 종종 나오는 **"기능 하나를 통째로 구현해보세요"** 유형의
연습 문제입니다. UI(카드, 리스트, 입력폼)는 이미 완성되어 있고, **상태와 핵심 로직만
`src/hooks/useTodoBoard.ts` 한 곳에 비어있습니다.**

## 요구사항 (화면 구조)

```
App
├─ Header: "Todo Board" 제목 + Reset 버튼
└─ Board
   ├─ TodoList (상단)
   │  ├─ AddTodoForm: 입력창 + "Add Todo" 버튼 → 새 카드 추가
   │  └─ 카드들: 각 카드에 "완료" 버튼 → 누르면 완료 영역으로 이동
   └─ CompletedList (하단)
      └─ 카드들: 각 카드에 "삭제" 버튼 → 누르면 완전히 제거
```

- **TODO 리스트**: `Add Todo`로 새 할 일 카드 추가 가능. 각 카드의 "완료" 버튼을 누르면
  그 카드가 TODO 리스트에서 사라지고 완료 영역으로 내려감
- **완료된 일감**: 완료 처리된 카드가 모이는 영역. 각 카드에 "삭제" 버튼이 있어서 누르면
  완전히 제거됨 (TODO로 되돌아가지 않음)
- **Reset 버튼**: 추가/완료/삭제했던 모든 변경을 되돌리고 초기 상태로 복원

## 구현해야 할 것: `useTodoBoard` 훅

```ts
export function useTodoBoard(): UseTodoBoardResult {
  // 여기를 구현하세요
}
```

파일(`src/hooks/useTodoBoard.ts`) 상단 주석에 정확한 초기 상태(시드 데이터)와
각 함수가 해야 할 일이 적혀있습니다. 그대로 따라서 구현하면 됩니다.

`App.tsx`와 모든 UI 컴포넌트(`Card`, `AddTodoForm`, `TodoList`, `CompletedList`)는
이미 완성되어 있고, 전부 `useTodoBoard`가 반환하는 값만 가지고 동작합니다 — 즉
**이 훅 하나만 제대로 구현하면 화면 전체가 동작**합니다. `Card`는 TODO 카드와
완료 카드가 함께 쓰는 단일 컴포넌트로, `actionLabel`/`onAction`/`completed` props로
두 영역의 차이(버튼 라벨, 취소선 스타일)만 다르게 주입받습니다.

## 실행 방법

```bash
npm install
npm run dev            # 브라우저에서 직접 확인
npm run test:watch     # 저장할 때마다 자동 채점 (9개 테스트)
npm run typecheck      # 타입 에러 확인
```

테스트는 두 종류입니다.
- `src/hooks/useTodoBoard.test.tsx` — 훅 자체의 동작을 단위 테스트 (5개)
- `src/App.test.tsx` — 실제 화면에서 클릭/입력하며 동작을 확인하는 통합 테스트 (4개)

## 생각해볼 것 (시작 전에)

- `todos`와 `completed`를 **완전히 분리된 두 개의 배열**로 관리할 수도 있고,
  하나의 배열에 `status: "todo" | "done"` 같은 필드를 둬서 필터링으로 나눌 수도
  있어요. 어느 쪽이 더 간단할까요? 각각의 장단점은 뭘까요?
- `addTodo`에서 새 항목의 `id`는 어떻게 만드시겠어요? (`crypto.randomUUID()`,
  타임스탬프, 카운터 등 — 유일하기만 하면 테스트는 통과합니다)
- `reset()`은 "완전히 빈 상태"가 아니라 "원래 시드 데이터로 되돌리기"예요. 이 둘의
  차이가 왜 중요할까요?
